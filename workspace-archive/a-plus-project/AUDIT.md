### Hash method validation
play.html and 3d.html already ship strict meta CSPs with sha256 lists. My computed hashes
for play.html match its meta list **35/35 exactly**; for 3d.html mine are a subset
(6 of meta's 8; 2 stale extras in the meta, harmless). The header map unions meta hashes
in for those two pages so the header never blocks anything the meta allows.

## Design — strict CSP built per page in the headers Worker
The Worker already fetches origin before setting headers, so it looks up the response's
URL path in a build-time map (hashmap.json, generated by gen_hashmap.py) and emits:

```
default-src 'self';
script-src 'self' https://accounts.google.com https://static.cloudflareinsights.com '<page script hashes>';
script-src-attr 'unsafe-hashes' '<6 handler hashes>';
style-src 'self' https://accounts.google.com '<page style-block hashes>';
style-src-attr 'unsafe-hashes' '<page style-attribute hashes>';
img-src 'self' data: blob: https:;
media-src 'self' data: blob:;
font-src 'self' data:;
connect-src 'self' https: wss:;
frame-src 'self' https://accounts.google.com;
worker-src 'self' blob:;
manifest-src 'self';
object-src 'none';
base-uri 'self';
form-action 'self' https://accounts.google.com;
frame-ancestors 'self'
```
- **No 'unsafe-inline' and no 'unsafe-eval' anywhere in script scope.** 'unsafe-eval' is
  provably unneeded (zero eval-family hits in all HTML+JS).
- Inline handlers + style attributes are covered by CSP3 'unsafe-hashes' with the exact
  hashes of the 6 handler bodies / per-page style values — the only standards mechanism
  that allows them without 'unsafe-inline'.
- Path normalization: exact, trailing-slash → /index.html, extensionless → +.html,
  strip-trailing-slash → /index.html. Unmapped HTML paths fall back to the global union
  set (~15.8 KB of hashes — rare path, measured during Phase 2).
- Per-page headers stay small: worst page (play.html) = 35 script hashes ≈ 1.9 KB total CSP.
- Other headers unchanged (HSTS, X-Frame-Options, XCTO, Referrer-Policy, Permissions-Policy).
- Known residual risks (Phase 2 must test): JS that sets inline styles at runtime
  (gate overlay/i18n) is governed by style-src-attr and may be blocked where values
  aren't in the page's static set — the union fallback does NOT cover mapped pages, so
  if Chromium testing shows dynamic-style violations, the fix within the header layer is
  to ship style-attr hashes as the union set on every page (68 hashes ≈ 3.6 KB) — decided
  by Phase 2 evidence, not by guessing. 'unsafe-hashes' browser support: Chrome/Edge full,
  Firefox ≥129, Safari ≥15.4 — acceptable coverage; unsupporting browsers ignore the
  keyword and handlers fail closed (buttons dead) — noted as the design's one real tradeoff.
